Annotation dimensions

Actor: visible or audible performer / source.

Character: represented role or identity.

Action: observable event or behavior.

Intention: communicative purpose inferred from context.

Speech: spoken content and its relation to the scene.

Emotion: affective tone conveyed in context.

Quality considerations

Labels must reflect audiovisual evidence rather than assumptions based on isolated words or gestures.

Distinguishing observable action from inferred intention supports consistent annotation.

Ambiguous cases require careful interpretation and adherence to the project's labeling criteria.

Relevance to AI data quality: turning unstructured audiovisual material into structured, semantically meaningful labels requires contextual judgment, consistent categorization, and clear boundaries between observation and interpretation.

CASE 02AI output evaluation

AI-Generated Subtitle Evaluation

Syntactic and semantic auditing · hallucination detection · severity assessment

15-category error framework · multimodal context · logical consistency
Open case study+

Syntax as a quality-audit tool for AI-generated text

This analytical case study applies syntactic and semantic principles to detect hallucinations and logical inconsistencies in AI-generated subtitles. It focuses on a critical distinction: fluency does not guarantee logical accuracy.

Core hypothesis: AI output failures often appear as systematic violations of syntactic-semantic relationships. Structural analysis can expose these failures even when the text looks fluent and superficially well formed.

Five-step audit protocol

1
Corpus collection

Video and AI-generated subtitles in Brazilian Portuguese and English.

2
Synchronized review

Frame-by-frame playback, audio/subtitle comparison, and deviation detection.

3
Dual classification

Assign an error category and a severity level.

4
Precise localization

Record the video timecode, subtitle line, and surrounding context.

5
Structured documentation

Normalize findings in a spreadsheet for analysis and engineering feedback.

Operational severity scale

MAJORComprehension is significantly impaired or ambiguity cannot be resolved from context.
MINORA noticeable deviation that does not prevent basic understanding.

Paradigmatic cases · select a failure mode

The examples below are translated and summarized from the original Portuguese analytical case. Original PT-BR screenshots are retained where they provide direct evidence.

Context: A prison guard gives instructions to a group of detainees. The AI treats the English pronoun “you” as singular, overlooking the collective visual context.
AI output · PT-BR screenshot
Contextual correction

Several detainees are standing in formation. The source audio contains collective commands, so the Brazilian Portuguese imperatives must be plural.

  • “Sacudam o cabelo.”
  • “Mexam os dedos das mãos.”
  • “Abram os dedos dos pés.”
  • “Levantem-se.”
  • “Virem-se.”
Detected failure: grammatical number was not resolved through visual context. The model selected singular imperative forms, violating agreement with the implied plural addressee. This is also a multimodal integration failure: the visual input that disambiguates “you” was not reflected in the output.

AI-generated subtitle
Audio-grounded interpretation

Intended PT-BR: “Bora, o povo, porque o busão chegou!”

AI output: “Fora o piovo, porque a impulsão chegou!”

The model changes an invitation into an expulsion (“Bora” → “Fora”), invents “piovo”, and misrecognizes “busão” as “impulsão”.

Detected failure: catastrophic semantic selection, phonetic-to-lexical confusion, and loss of referential grounding. The generated sentence remains syntactically plausible but has no coherent interpretation in the scene.

Python fundamentals · standardization
Open case study+

Standardizing the structure before automating the task

This Python exercise establishes a predefined structure and fields for a subtitle-related annotation workflow. Its purpose is standardization, not automatic annotation.

What the script does

  • Sets up a consistent template.
  • Defines the expected fields and their order.
  • Provides a repeatable structure for manual data entry.

What it does not do

  • It does not perform NER.
  • It does not identify speakers or voices automatically.
  • It does not infer actors, intentions, or emotions.
  • It does not populate annotation fields autonomously.
annotation_template.pyPython · manual annotation structure
# Define a consistent structure for manual annotation.
# Values are completed by the annotator; no automatic labeling.

annotation = {
    "actor": "",
    "character": "",
    "action": "",
    "intention": "",
    "speech": "",
    "emotion": ""
}

Development direction: learning NLP methods such as named entity recognition and speaker identification is a future learning goal, not a capability claimed by this project.
